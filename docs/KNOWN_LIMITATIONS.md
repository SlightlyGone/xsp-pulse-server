# Known limitations

- **Development API key:** The API uses a shared bearer key rather than individual identities, expiry or fine-grained authorization. Anyone holding it can call the protected endpoint. The current server code has a fallback key value if `APP_API_KEY` is missing; configure a strong explicit value. Add proper secret management, rotation, access control and rate limiting before broader use.
- **Android key exposure:** The development key is packaged into the Android app as an asset and can be extracted. It must not be treated as a production secret. The Windows app reads a local per-user file; protect that file and avoid distributing credentials.
- **Ephemeral Oracle IP:** The current hostname encodes an ephemeral public IP. An address change can break HTTPS access and installed clients. Use a stable address and managed hostname, with an update and certificate plan, for reliable operation.
- **Observation freshness:** Snapshots are held in memory; prices and timestamps remain from the last observation during disconnects or quiet markets. API reads now report `STALE` above per-instrument receipt-age thresholds and `WAITING_FOR_DATA` before the first event; see [freshness semantics and configuration](../README.md#observation-freshness). There is no trading-session calendar: old observations during closures, holidays, scheduled breaks or sparse XSP trades are expected and do not establish a connection failure. `STREAMING` describes recent local receipt, not exchange latency or price validity; `/health` only tests HTTP responsiveness. XSP values are derived from trades, not an XSP bid/ask quote. There is no automatic staleness watchdog, alerting or reconnect action.
- **Symbol switching:** The UI retains the previous snapshot while it fetches the newly selected symbol, so the old symbol and price can briefly remain visible after switching. Failed requests can prolong this state.
- **Production hardening:** Add robust authentication and authorization, secret lifecycle management, safe observability and alerting, dependency pinning and update testing, reproducible isolated deployment environments, backup and rollback drills, and resilience and end-to-end tests. Review TLS, firewall, rate limiting, monitoring, and market-data entitlement and licensing requirements for the intended use. The current shared virtual environment is a rollback dependency.
